## Defect and change

The earlier copy2-based helper reproduced ACL and extended-attribute loss while reporting file-tree success. A new independent scripts/synthetic_data_preservation.py module retains the original root inode and compares the complete namespace, original absence, file bytes and root/directory/file metadata. Its Darwin backend records ordered ACL text with principal UUIDs, complete binary xattr names/values (including empty values), permission bits, uid/gid, supported flags and nanosecond mtimes. Original nonzero flags, unsupported ownership, unreadable metadata, links/hardlinks and special files stop before the body. Trial links/special files are moved into quarantine without following them.

The implementation copies with ditto --rsrc --extattr --acl, explicitly reapplies recorded metadata and compares the resulting inventory. On this host, ditto alone omits zero-byte xattrs on directories; explicit application is therefore necessary. Exact attribute replacement removes trial-only attributes. Metadata is applied to the retained root and quarantine root after child moves. Backup, staging, quarantine, restored data and original backup are checked separately. A complete verified stage is required before any trial file moves. Copy/metadata errors retain original and trial evidence with BACKUP_FAILED or RECOVERY_REQUIRED. A durable rename journal supports explicit recovery after an interrupted disposable test; core restoration never deletes prior original/trial evidence. Test cleanup removes only its own synthetic workspace.

The public transaction/inventory API requires its marked synthetic workspace. Outsider paths are rejected lexically before stat/resolve; symlink ancestors and changed workspace identity are rejected. This prevents accidental use on arbitrary app paths; it is not a security sandbox for hostile Python callers.

## Explicit remaining verification

A synthetic success receipt always has syntheticOnly=true and nativeRestorationCertified=false. Access, birth and change timestamps, external stores, actual writer quiescence and effective-preferences cache state are outside this certification. uid/gid are compared, not repaired with elevated privileges; original nonzero flags fail closed. ACL inheritance and file metadata are captured as present on these same-host fixtures; this does not qualify every filesystem, principal migration, protected xattr or arbitrary restrictive ACL combination. Any unsupported/read/write failure must remain a blocker.

No method for synchronizing the actual owned preference domain/queued writer has been established or run. Stable bytes or a callback returning true do not prove that boundary. The future native method still needs authorized lifecycle/cache evidence and an unoverridden relaunch proving the effective AppLanguageStore/UI choice agrees with original persistent state and post-lifecycle inventory. Do not wire this module into the native runner or treat these tests as approval to do so. Current Help provenance remains missing3/stale4 and the bundled full asset gate remains blocked; no Help image or manifest is regenerated by this change.
