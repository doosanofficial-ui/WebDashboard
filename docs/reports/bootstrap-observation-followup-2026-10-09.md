## Minimal change

`run_owned_phase` now records Timeout observation time, original error/source and cached child returncode without synchronous resource/native sampling. Resource time/data and executable identity remain unknown, with a fixed deferred reason. The existing completion Event is set only after this cheap snapshot is complete. A late cached exit0 is preserved while the result stays Timeout. Non-Timeout sampling remains unchanged. Existing post-stop diagnosis is separate and cannot overwrite the first snapshot or resample a reaped original PID. Main's progress/receipt work and the separate `simctl_output` failure path can still delay cleanup; this is not a total wall-time guarantee.

The existing single boot-stream worker adds24 fixed10-second buckets using complete-line processing monotonic observations. These are not kernel receive times, historical reconstructed times or subscription readiness. Each bucket keeps fixed numeric sender/drop counters, event-UTC extrema and reader-progress observations. Nonmonotonic event UTC does not reorder received observations. Empty, unobserved and stopped intervals keep readiness unknown; events processed outside the original read window are counted separately. Reported renderer, MCM migration, reminders migration and LaunchServices paths are matched against sanitized actual first-CI rows; they do not prove whole-Simulator readiness or executable identity. Raw messages, arbitrary field names/paths and invalid UTC text are absent from the summary. Summary faults cannot discard an otherwise UUID-valid raw record.

Schema3 supersedes the schema2 allocation in [the tail report](boot-stream-tail-observation-2026-10-09.md) for new captures. The default combined file-payload cap remains2MiB:896KiB head +512KiB tail +512KiB atomic tail staging +64KiB full receipt +64KiB atomic receipt staging. `byteLimit` remains the requested raw-retention/staging cap for smaller synthetic fixtures; `retainedPayloadByteLimit` is the combined2MiB limit. Receipt UTF-8 size is checked before atomic publication; oversized metadata gets a bounded fixed-key receipt marked truncated. Failed replacement preserves the prior receipt. Filesystem allocation, process RSS and parser work are separate from this payload cap. Original archives and retained raw line bytes are preserved; the new head/tail partition differs because metadata is reserved.

No process, file, probe or thread beyond the existing worker/receipt writer is added. Boot60/bootstatus180, diagnosis20/probe3, collector read240, app build600/UI1200, original error predicates and owned-group cleanup remain unchanged. The Telemetry app, user records/settings, physical device and shared Simulator are outside this change.
